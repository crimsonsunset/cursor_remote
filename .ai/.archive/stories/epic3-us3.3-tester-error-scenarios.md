# Epic-3 - 用户故事-3.3 (PRD US3.3)

测试者 - 错误场景模拟与验证

**作为** 测试者
**我希望** 模拟不同的错误场景（如AppleScript执行失败、Cursor无响应、无效指令等）
**以便** 验证错误信息能否正确传递并在客户端展示。

## Context

{

- 当前状态: 核心功能路径已可测试。

}

## Tasks

{
1. - [ ] 列出潜在的错误场景清单，包括但不限于：
   1. - [ ] AppleScript执行失败（例如，脚本自身错误、目标应用未运行）。
   2. - [ ] Cursor应用无响应或超时。
   3. - [ ] 客户端发送无效或服务器无法解析的指令格式。
   4. - [ ] Supabase通信错误（例如，网络中断瞬间）。
   5. - [ ] 权限问题（如果RLS已初步配置）。
2. - [ ] 为每个错误场景设计测试用例，明确如何模拟或触发错误。
3. - [ ] 执行测试用例，并观察以下几点：
   1. - [ ] 服务器端是否正确捕获错误并记录到`commands.last_error`和`results.error_message`。
   2. - [ ] `commands.status`是否正确更新为'error'，`results.is_error`是否为TRUE。
   3. - [ ] 客户端是否能接收到错误状态和错误信息。
   4. - [ ] 客户端是否以清晰、合理的方式向用户展示错误信息 (参考US2.4/PRD-US7Cli)。
   5. - [ ] 系统是否在错误发生后保持稳定，不会崩溃。
4. - [ ] 记录每个错误场景测试的结果。
}
