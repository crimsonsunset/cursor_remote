# Epic-3 - 用户故事-3.1 (PRD US3.1, US8 & US9)

用户 - 端到端聊天与动作指令验证

**作为** 用户
**我希望** 能通过迁移后的客户端发送"聊天"（包含不同模式）和"执行动作"类型的自然语言指令，服务器能正确通过AppleScript驱动Cursor执行
**以便** 我能在客户端实时看到Cursor返回的准确结果或错误信息。

## Status

草稿

## Context

{
- 背景信息: 此故事验证核心用户交互是否在新架构下按预期工作。
- 当前状态: 客户端和服务器端已初步集成Supabase。
- 故事理由: 确保迁移后，用户最常用的功能（聊天、执行动作）能够端到端顺畅运行。
- 技术背景: 涉及完整的流程：客户端发送 -> Supabase -> 服务器处理 -> AppleScript -> Cursor -> 结果返回Supabase -> 客户端显示。
}

## Tasks

{
1. - [ ] 准备一组代表性的"聊天"指令（例如，不同模式：agent, ask）。
2. - [ ] 准备一组代表性的"执行动作"指令（例如：新建聊天, 清除聊天, 保存代码, 运行代码）。
3. - [ ] 通过客户端发送这些"聊天"指令：
   1. - [ ] 验证服务器是否正确接收并通过AppleScript驱动Cursor执行。
   2. - [ ] 验证Cursor的回复是否通过Supabase正确返回并在客户端显示。
   3. - [ ] 验证错误情况（如无效聊天指令）是否能正确处理并显示错误。
4. - [ ] 通过客户端发送这些"执行动作"指令：
   1. - [ ] 验证服务器是否正确接收并通过AppleScript驱动Cursor执行相应动作。
   2. - [ ] 验证操作结果或确认信息是否通过Supabase正确返回并在客户端显示。
   3. - [ ] 验证错误情况（如无效动作指令、动作执行失败）是否能正确处理并显示错误。
5. - [ ] 记录测试的指令、预期结果和实际结果。
}
